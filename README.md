# novel-dl

一个**只做一件事**的小说下载器：**给一个章节目录页的地址，把整本书完整、正确、快速地下载下来。**

不做多源聚合搜索，不内置任何站点规则，不模仿浏览器绕反爬。
范围小，所以能把**断点续传、并发、容错**这三件事做到可验证。

## 性能（本机基准，`tests/bench.py`）

本地模拟站点，60 章，每章 30ms 网络延迟：

| 并发 | 耗时 | 加速比 |
|---|---|---|
| 1（串行） | 3.43s | 1.00x |
| 2 | 1.65s | 1.94x |
| 4 | 0.97s | 3.31x |
| 8 | 0.85s | 3.76x |

带 3% 失败率（模拟站点限流）时，8 并发仍有 **3.79x** —— 因为有专门的
两阶段重试，坏章不会拖住整批。

```bash
novel-dl <url> -w 4        # 4 线程并发
```

## 三个核心机制

### 1. 断点续传：正文每章即落盘，账本批量落盘

```
books/<站点目录>/
├── cache/00001.txt      ← 一章一个文件，原子写入（tmp + rename）
├── cache/00002.txt        断电最多丢一章，且不会留半截文件
├── state.json           ← 账本：目录快照 / 已完成 / 失败名单
└── 书名.txt              ← 合并成品
```

- **正文每章立即写盘**：Ctrl+C、断电、关窗口都不丢已下载内容。
- **账本按批落盘**：每章都重写整个 `state.json` 会让总开销变成 O(n²)
  （2000 章的书光这一项就浪费近 40 秒）。改成每 20 章落盘一次。
- **`recover_from_disk()`**：启动时扫描 `cache/`，把「文件还在、账本没记」
  的章节补回账本，所以账本滞后不会导致重复下载。

### 2. 增量更新：重跑同一条命令

目录快照与网站实时目录对比，只下新增章节。目录结构变化时（站点改版），
按章节 URL 重映射已有进度并迁移缓存文件，不会把旧进度安到错误章节上。

### 3. 两阶段并发重试

并发下最怕「一个坏章占住一个线程 20 秒」。所以：

```
阶段 1：所有章节各试一次，失败立即跳过，记入待重试列表
阶段 2：整批扫完后，对待重试章节做 3 轮补抓（轮间 0.8s / 2.0s / 4.0s）
```

退避由引擎在**轮次之间**统一控制，而不是在单个线程里 `sleep`。
配合 fetcher 里的**抖动退避**（0.75~1.25 倍随机），避免多线程同时重试
形成 thundering herd —— 那在站点看来就是攻击，只会被封更久。

## 稳定性是被测试证明的，不是声明

```bash
python tests/test_all.py         # 21 项：功能 / 规则 / 网址纠错
python tests/test_stability.py   # 21 项：并发 / 中断 / 崩溃恢复
python tests/bench.py            # 性能基准（可注入延迟与失败率）
```

稳定性测试专门攻击边界情况：

| 攻击 | 断言 |
|---|---|
| 8 线程抓 60 章 | 不丢章、**不串章**（逐章校验文件内容对应正确章号） |
| 并发请求去重 | 每章只请求一次 |
| 中途停止 | 2 秒内退出，已下章节保留，账本不损坏 |
| 模拟断电（不 flush） | 重跑时已下章节**不重复请求** |
| 3 线程并发强制落盘 500 次 | 账本始终是合法 JSON，无写入异常 |
| 每 10 章坏一个 | 坏章记账、好章全成、TXT 只含成功章节 |
| 老式 `fetch(url)` 签名的插件 | 仍可工作（新增参数不是破坏性变更） |

## 安装

```bash
pip install -e .
# 或带 Selenium 支持（动态渲染站点）
pip install -e ".[selenium]"
```

Python 3.10+。

## 用法

```bash
# 全本下载
novel-dl https://example.com/book/123/

# 并发
novel-dl https://example.com/book/123/ -w 4

# 只下 100~200 章
novel-dl https://example.com/book/123/ -f 100 -t 200

# 被限速：调大间隔、调小并发
novel-dl https://example.com/book/123/ --delay 3 -w 1

# 断了或网站更新了：重跑同一条命令
novel-dl https://example.com/book/123/
```

网页控制台：`python webui.py`（或双击 `novel-dl.bat`）。

## 配置

`novel-dl.toml`（当前目录）或 `~/.novel-dl/config.toml`：

```toml
output_dir = "books"
driver     = "requests"
delay      = 0.5
workers    = 4
```

优先级：命令行 > 配置文件 > 默认值。

## 它不做什么

- **不内置站点规则**：本仓库不包含任何具体网站的选择器。规则由使用者提供，
  格式见 [docs/RULES.md](docs/RULES.md)。通用启发式解析能应付不少静态站。
- 不做验证码识别、不执行页面解密脚本、不绕付费墙。
- 请自行确认目标站点的 `robots.txt` 与使用条款；下载内容版权归原作者所有。

## 架构

```
novel_dl/
├── __main__.py   # CLI（argparse）
├── engine.py     # 编排：目录 → 增量对比 → 串行/并发抓取 → 跳过 → 合并
├── fetchers.py   # 抓取层插件（requests / selenium），注册表切换
├── parser.py     # 解析层插件：规则解析器 + 通用启发式
├── rules.py      # 规则加载 / 域名匹配 / url_fix 纠错
├── progress.py   # 断点续传账本  ← 最值得读的文件
├── textutil.py   # 正文噪声过滤
├── config.py     # TOML 配置
└── log.py        # 统一日志
```

三个扩展点，都是「新增一个类 + 一行注册」：

- 新抓取策略 → 继承 `fetchers.BaseFetcher`，`@register("名字")`
- 特殊站点解析 → 继承 `parser.BaseParser`，`@register_parser("域名片段")`
- 普通网站 → 不用写代码，加一条 JSON 规则
