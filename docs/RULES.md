# 站点规则格式

程序本身**不内置任何具体网站的规则**。你写的规则放在哪、怎么匹配、字段是什么，都在这一页。

## 规则文件放在哪

按顺序查找，同 host 只取第一次出现的：

1. 环境变量 `NOVEL_DL_RULES` 指向的文件（多个用系统分隔符隔开，Windows 是 `;`）
2. 当前工作目录下的 `sites.json`
3. `~/.novel-dl/sites.json`
4. 包安装目录里的 `sites.json`

文件是 **JSON 数组**，一个元素一条规则。读取失败只警告并跳过，不会影响其他来源。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `host` | ✅ | 域名，用于匹配。子域也会命中（`www.a.com` 能用 `a.com` 的规则）。留空则从 `url` 里推 |
| `name` | | 站点名，只用于日志显示 |
| `url` | | 站点首页，仅供人看；`host` 缺失时从这里推出域名 |
| `toc_item` | | **目录页**章节链接的 CSS 选择器 |
| `toc_desc` | | 设为 `true` 表示目录是倒序，解析后整体反转 |
| `ch_title` | | **章节页**标题的选择器 |
| `ch_content` | | **章节页**正文容器的选择器 |
| `filter_tag` | | 要从正文里删掉的标签，逗号分隔（如 `script, style, .ad`） |
| `filter_txt` | | 要从正文里删掉的正则，用 `\|` 分隔多条 |
| `next_page` | | 章节内分页的「下一页」链接选择器（可选，引擎也会自動按 URL 序号推断） |
| `url_fix` | | 网址纠错规则，`[["正则","替换"], ...]`，依次 `re.sub` |

`toc_item` / `ch_title` / `ch_content` 里如果带了 so-novel 风格的 `@js:` / `@java:`
后缀，会被**自动剥离**，只按纯选择器取文本。本项目不在页面里执行 JS——
依赖 JS 解密才能拿到正文的站点，请改用 `--driver selenium` 或自己写解析器。

## 最小示例

```json
[
  {
    "host": "example.com",
    "name": "示例站",
    "toc_item": "dl.list dd a",
    "ch_title": "h1.title",
    "ch_content": "#content",
    "filter_tag": "script, style, .ad",
    "filter_txt": "请记住本站域名|手机用户请浏览"
  }
]
```

## 怎么写一条规则

1. **先不加规则直接跑**。通用解析器能应付不少静态站，跑通了就不用写规则。
2. 跑不通时，在浏览器里打开目录页，`F12` → 选中一章的链接 → 看它的 CSS 路径，
   填进 `toc_item`。技巧：选器尽量只锚定「章节列表容器」，别写成整页通用的 `a`。
3. 打开任意一章，同样方法找标题和正文容器。
4. 正文里混进广告/导航时，先用 `filter_tag` 删元素（更干净），再用 `filter_txt` 删残留文本。
5. 改完重跑同一条命令即可，已下载章节不会重下。

### 常见坑

- **目录里混着「最新章节」块**：选择器锚定主列表（如 `#list dd a`），别用裸 `a`。
- **图标字体混淆**：章号的字被替换成私有区字符（U+E000–U+F8FF）。
  通用解析器会按 URL 形态聚类识别，规则解析器会剥掉这些字符并补回「第」。
- **章节分页**：一章拆成 `/123_2.html`、`/123-3.html` 等。
  引擎会自动识别「当前页序号 +1」的链接并合并；识别不了就配 `next_page`。
- **正文过短被判失败**：正文少于 50 字会当成「解析失败或触发反爬」跳过。
  确实是短章节（如卷首语）时，这属于预期行为，账本里会记为失败并在下次重试。

## 调试

```bash
novel-dl <url> -v          # 输出调试日志，能看到选择器命中/回退过程
```

规则里的选择器写错不会让程序崩溃：会打印警告并**自动退回通用解析器**。
